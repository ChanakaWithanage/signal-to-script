Automate TradingView Signals with a Chrome Extension—Without a Paid Bot Service

Your indicator already knows when to buy or sell. What if that signal could go a step further and place the order on an exchange? A small Chrome extension offers an interesting way to connect TradingView alerts to Binance Futures without paying a separate automation platform every month.

By CW · Pine Script v6 · Browser-based trading automation guide

The idea: let your signal do more than send a notification

TradingView makes it easy to build indicators and strategies. A Supertrend reversal might display Buy when the trend turns bullish and Sell when it turns bearish. But a chart signal does not automatically place a Binance Futures order.

There are services that connect alerts to exchanges, often with another subscription or a hosted webhook receiver. For someone experimenting with one or two custom scripts, that can be more infrastructure than they really want.

The alternative worth exploring is a local Chrome extension. The indicator produces an alert, the TradingView Alerts Log shows it, and the extension reads that signal and sends an authenticated API request to the exchange. No separate paid bot platform or dedicated backend is required for the proposed design.

Start with a real strategy: Supertrend + DEMA

We've already shared a Supertrend + DEMA Reversal Strategy in Pine Script v6. It calculates Supertrend using a configurable source, including DEMA(50), and can reverse simulated long and short positions when the trend changes.

The strategy already has buy and sell alert calls. For the extension design, we don't need to rewrite the strategy's trading logic. We need to make the alert messages more explicit, so the extension understands what action to take and which signal it has received.

View the actual Supertrend + DEMA Pine Script v6 source on GitHub.

One small change to the alerts

A message like “BUY” works for a human, but it's not enough to safely operate a Futures account. I would use a structured JSON message like this:

{
  "source": "TV_FUTURES_EXTENSION",
  "symbol": "BTCUSDT",
  "action": "OPEN_LONG",
  "signal_id": "BTCUSDT-60-1794048000000-LONG"
}

The extension can support four clear actions: OPEN_LONG, OPEN_SHORT, CLOSE_LONG and CLOSE_SHORT. A new Supertrend buy signal could use OPEN_LONG; if a short is already open, the extension should first close it and then open the long, only after confirming the exchange position.

Inside the existing Pine v6 script, the alert-generation portion could be adapted along these lines. This is an illustrative excerpt, not a separate ready-to-run strategy; it would replace the existing simple buy/sell alert calls:

string exchangeSymbol = input.string("BTCUSDT", "Execution Symbol")

if buySignal
    alert('{"source":"TV_FUTURES_EXTENSION","symbol":"' +
      exchangeSymbol + '","action":"OPEN_LONG","signal_id":"' +
      exchangeSymbol + '-' + str.tostring(time_close) + '-LONG"}',
      alert.freq_once_per_bar_close)

if sellSignal
    alert('{"source":"TV_FUTURES_EXTENSION","symbol":"' +
      exchangeSymbol + '","action":"OPEN_SHORT","signal_id":"' +
      exchangeSymbol + '-' + str.tostring(time_close) + '-SHORT"}',
      alert.freq_once_per_bar_close)

Using a signal ID helps the extension recognize an alert it has already processed. The extension still needs independent checks against the actual exchange account before placing an order.

How the Chrome extension would work

The first version would be deliberately small. A Chrome content script watches the TradingView alert log for new entries and passes relevant messages to the extension's background service worker. That service worker validates the JSON and, once automated execution is enabled, makes the signed request to Binance.

  1. Create the TradingView alert. Select the strategy's alert() function calls only condition and let TradingView record the custom JSON whenever the script signals.
  2. Open TradingView in Chrome. The extension monitors the currently accessible alert log. It must be tested against the live TradingView interface, which can change.
  3. Configure the exchange. Choose Binance USDT-M Futures Demo Trading, the permitted symbols, a trading size and a maximum position size.
  4. Process a new signal. Validate its source, timestamp, symbol, action and unique ID. Ignore duplicates and anything outside the user's allowed settings.
  5. Check the existing position. A close action must reduce an existing position, never accidentally open a new position in the opposite direction. For a reversal, confirm the close before placing the new order.
  6. Verify the exchange result. Record the order ID, fill status and any errors. If the exchange state is uncertain, pause instead of sending another order blindly.

The extension could also have a compact popup for Demo/Live mode, approved symbols, trade size, a pause switch and recent execution history. Those are proposed controls; there isn't a published production-ready extension or verified execution demo for this article yet.

Why use a browser extension instead of a paid bot platform?

  • No separate automation-service subscription. The bridge can run locally without paying an ongoing third-party bot platform just to forward a signal.
  • Your own trading logic. We can adapt the alert format to Supertrend, EMA crossovers, breakout indicators, custom strategies and other scripts whose signals are accessible and can be expressed as alerts.
  • Direct exchange integration. The first exchange adapter can target Binance USDT-M Futures. A Bybit adapter or another supported exchange can be added later.
  • Clear control over order behavior. Rather than assuming Buy always means “open long,” the extension can use explicit actions, check positions and enforce trade limits.
  • Reusable approach. Once the integration is built and tested, the same extension architecture can be reused with different Pine Script alerts.

What about Binance and Bybit?

Binance USDT-M Futures exposes signed order APIs, including market orders, and provides a Futures demo endpoint. The proposed initial version targets Binance with one-way position mode. More complicated position modes need separate handling.

Bybit's V5 API also supports order placement, including derivatives, but it uses different request formats and account rules. Extending the bridge to Bybit is possible by implementing and testing another exchange adapter; it is not something a Binance-only build supports automatically.

Is this completely free?

There would be no required subscription to a third-party automation service for this browser-only approach. You could run your own extension locally, without paying for hosting or a separate webhook platform.

But there are two important distinctions. First, TradingView's free Basic plan currently does not include technical alerts for indicators or strategies, so you may still need a TradingView subscription to generate these alerts. Second, exchange trading fees and any market-data or other account charges still apply. See TradingView's current plan comparison.

Because the extension reads an on-screen alert log, your browser and TradingView session need to remain available. It is not a 24/7 server replacement: a sleeping computer, closed tab or changed TradingView page can interrupt the workflow. Secure local API-key handling, duplicate protection and exchange reconciliation are also essential before considering live trading.

Where the implementation stands

The Supertrend strategy and its Pine v6 source are already available. The Chrome extension, TradingView log reader and Binance execution bridge described here are a proposed integration design, not a published or end-to-end-verified trading bot. The extension repository and setup screenshots can be linked here once a working demo version is ready.

The right order is to validate alert-log detection, verify signal parsing, execute mock orders, test Binance Futures Demo Trading, and only then consider live trading.
